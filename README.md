# 志工居家訪視表單電子化系統

行動裝置優先、大按鈕點擊式的志工居家訪視電子化填報平台。

| 項目 | 技術 |
|------|------|
| 前端 | 純 HTML / CSS / Vanilla JS |
| 後端 | Google Apps Script (GAS) Web App |
| 資料庫 | Google Sheets |
| 部署 | Render Static Site (免費) |

---

## 🚀 部署步驟（依序完成）

### Step 1 — 建立 Google Sheets 主試算表

1. 前往 [Google Sheets](https://sheets.google.com) 新增一個空白試算表
2. 將試算表命名為「**志工訪視系統_主資料庫**」（或任何您喜歡的名稱）
3. 記下試算表的網址，格式為：
   ```
   https://docs.google.com/spreadsheets/d/【這段是試算表ID】/edit
   ```

---

### Step 2 — 部署 Google Apps Script (GAS) 後端

#### 2-1 建立 Apps Script 專案

1. 在試算表中點擊上方選單：**擴充功能 → Apps Script**
2. 進入 Apps Script 編輯器

#### 2-2 貼上後端程式碼

1. 將 `gas/Code.gs` 的全部內容**複製貼上**至編輯器的 `Code.gs`
2. 點擊 **「+」** 新增檔案，命名為 `InitSheet`
3. 將 `gas/InitSheet.gs` 的全部內容**複製貼上**至新建的 `InitSheet.gs`

#### 2-3 初始化試算表結構

1. 在編輯器上方下拉選單選擇函式：`initializeSheets`
2. 點擊 **▶ 執行**
3. 首次執行需授予試算表存取權限，點擊「允許」
4. 執行完成後，4 張工作表將自動建立：
   - `訪視紀錄表`
   - `人員帳號管理`（含 10 筆範例人員）
   - `分隊對照表`（3 個分隊）
   - `訪視題庫`（5 道題目）

#### 2-4 部署為 Web App

1. 點擊右上角 **「部署」→「新增部署作業」**
2. 類型選擇：**網路應用程式**
3. 設定如下：

   | 設定項 | 值 |
   |--------|-----|
   | 說明 | 志工訪視 API v1.0 |
   | 執行身分 | **我** (Me) |
   | 存取權限 | **所有人** (Anyone) |

4. 點擊 **「部署」**
5. **複製部署後的網址**（格式：`https://script.google.com/macros/s/【...】/exec`）

---

### Step 3 — 設定前端 API 網址

開啟 `frontend/app.js`，找到第 15 行：

```js
// 修改前
GAS_API_URL: 'YOUR_GAS_WEB_APP_URL_HERE',

// 修改後（填入您的 GAS Web App 網址）
GAS_API_URL: 'https://script.google.com/macros/s/AKfycbx.../exec',
```

---

### Step 4 — 上傳至 GitHub

```bash
# 在本專案資料夾中初始化 Git
git init
git add .
git commit -m "初始化：志工訪視系統"

# 建立 GitHub 新 Repo（在 github.com 操作後）
git remote add origin https://github.com/【您的帳號】/volunteer-visit-app.git
git push -u origin main
```

---

### Step 5 — 部署至 Render Static Site

1. 前往 [Render Dashboard](https://dashboard.render.com)
2. 點擊 **New → Static Site**
3. 連結您的 GitHub 儲存庫
4. 設定如下：

   | 設定項 | 值 |
   |--------|-----|
   | Name | volunteer-visit-app |
   | Root Directory | （留空） |
   | Publish directory | `frontend` |
   | Build command | （留空） |

5. 點擊 **Create Static Site**
6. 部署完成後取得網址（格式：`https://volunteer-visit-app.onrender.com`）

## ✏️ 自訂人員與分隊

所有設定直接在 Google Sheets 修改，前端會即時連動：

### 新增人員
在 `人員帳號管理` 工作表中新增一列：
```
所屬大隊 | 所屬單位 | 職稱 | 姓名 | 身分證字號 | 手機 | 權限角色
```

#### 權限角色對照

| 角色 | 可否填報訪視表 | 儀表板可檢視範圍 |
|------|---------------|-----------------|
| `管理員` | 可 | 全部分隊 |
| `大隊承辦人` | **否**（登入後直接進儀表板） | 所屬大隊底下**所有單位** |
| `分隊承辦人` | 可 | 僅**自己所屬單位** |
| `志工` | 可 | **不可檢視**（無入口，直接開網址也會被後端擋下） |

> **大隊承辦人的範圍怎麼決定**：以該員「所屬大隊」欄的值為準，
> 系統會找出同一大隊底下的所有單位。所以同一大隊的人，「所屬大隊」欄
> 必須填一模一樣的名稱（多一個空格或用簡稱都會被視為不同大隊）。

#### 儀表板「活躍志工榮譽榜」怎麼計算

欄位是**參與次數**，不是訪視戶數：一筆訪視紀錄裡，**主填寫人和每一位協同志工各算一次參與**。所以一筆 4 個人一起去的紀錄，4 個人各 +1，加總會大於總訪視戶數，這是正常的。

- 同一筆紀錄裡若同一個人重複出現（例如主填寫人又被勾成協同志工），只計一次
- 同名但不同分隊的人會分開統計
- 統計對象是「協同志工」欄位裡的名字，所以志工填報時務必確實勾選同行人員，沒勾到的人就不會被計入

### 新增分隊
在 `分隊對照表` 新增一列：
```
分隊名稱 | 分隊承辦人帳號 | 分隊專屬試算表ID（可留空） | 所屬大隊（可留空）
```
> 「所屬大隊」是輔助欄位。大隊範圍主要由 `人員帳號管理` 的所屬大隊決定，
> 若某個單位在人員表中還沒有任何人員，可在此欄補填，讓它也納入該大隊。

### 修改訪視題目

**題庫是唯一真相來源**：所有題目都在 `訪視題庫` 工作表維護，不需要修改程式碼，也不需要重新部署 Web App。

#### 新增一題
1. 在 `訪視題庫` 新增一列，題目代碼**沿用下一個號碼**（例：防火宣導已有 F01~F25，就填 `F26`）
2. 想讓它出現在某題後面，直接**拖曳該列**到想要的位置（顯示順序 = 列的順序）
3. 回到試算表選單 **「志工訪視系統 → 🔄 同步題庫欄位」**
4. 完成。志工端下次載入表單即出現

> 答案是以「題目代碼」對應欄位寫入的，因此調整列順序、或在中間插入新題目都**不會**讓既有答案錯位。

#### 停用一題
把該列的 `啟用` 欄改成 `FALSE`。題目不再出現於表單，但紀錄表欄位與歷史資料完整保留。
**請勿直接刪除題目列**——欄位對應會消失，過去的填答就查不回來了。

#### 各欄位說明

| 欄位 | 說明 |
|------|------|
| 題目代碼 | 同時是「訪視紀錄表」的欄位名稱。**用過就不要改名或重複使用** |
| 訪視類型 | `防火宣導` 或 `防災宣導` |
| 依賴條件 | 格式 `題目代碼=答案`（例 `F01=是`），該題答成此答案時才顯示本題。目前僅支援單一條件 |
| 題型 | `是否題` / `單選題` / `複選題` / `簡答題` / `日期題` / `數字題` |
| 選項內容 | 以**半形逗號**分隔，例如：`良好,普通,稍微疲倦`。簡答題、日期題、數字題留空 |
| 必填 | `TRUE` 為必填，`FALSE` 或留空為選填 |
| 啟用 | `FALSE` 為停用，留空或 `TRUE` 為啟用 |
| 答否建議 | 該題答「否」時要自動勾選的改善建議，多項以半形逗號分隔 |

#### 改善建議的自動勾選

在題目的 `答否建議` 欄填入建議文字，該題答「否」時就會自動勾選。系統會自動找到
同一宣導類型中「題目分類＝改善建議」的複選題（防火→F23、防災→D18）當作對象，
不需要指定。

```text
題目代碼  ...  答否建議
F16       ...  勿在逃生通道堆放雜物
F02       ...  更換合格瓦斯鋼瓶,定期檢查瓦斯桶與皮管     ← 一題可帶多項
```

- 建議文字必須與該建議題的**選項一字不差**，否則會被略過（瀏覽器主控台會留下警告）
- 多個題目可對到同一項建議，此時要**所有**觸發題都改成「是」，該建議才會自動取消
- 志工**手動**勾選的項目不會被系統取消
- 改完不需重新部署，志工端下次載入表單即生效
- 第一次使用可執行選單的 **「📋 填入預設連動規則」**，一鍵帶入既有的 21 條對照
  （只會填空白的儲存格，不覆蓋你改過的內容）

> 有兩條規則性質不同，仍寫在程式裡：F20／F21 的「購設消防設備」（需判斷複選題內容，
> 非單純答否）、D17 災害了解程度（依答「否」題數評級）。

> ⚠️ 「🔄 同步題庫欄位」只會**新增**欄位，不會刪除或搬移既有欄位與資料；
> 它同時會補齊各分隊專屬試算表的標題列。忘記點也沒關係——志工送出表單時系統會自動補上缺少的欄位。

> 💡 選單沒出現？重新整理一次試算表頁面即可（自訂選單在開啟試算表時才建立）。

### 設定跑馬燈公告

頁面上方的跑馬燈內容維護於 `系統公告` 工作表。**沒有任何公告時，跑馬燈整條不會顯示。**

首次使用請先點選單 **「志工訪視系統 → 📢 建立系統公告表（跑馬燈）」** 建立工作表。

| 欄位 | 說明 |
|------|------|
| 公告內容 | 要顯示的文字。**留空即不顯示該則**；可填多列，會依序輪播 |
| 啟用 | 填 `FALSE` 暫停顯示（內容保留，之後改回 `TRUE` 即可再用）；留空或 `TRUE` 表顯示中 |
| 顯示頁面 | 留空或 `全部`＝三個頁面都顯示；`登入頁`＝只在登入畫面（適合系統維護公告）；`填報頁`＝只給志工看；`儀表板`＝只給承辦人看。要指定多個頁面可填 `填報頁,儀表板` |

- 改完**不需要重新部署**，使用者下次載入頁面即生效
- 跑馬燈跟著頁面捲動，不會固定佔住手機畫面
- 滑鼠移上去（或鍵盤聚焦）會暫停捲動，方便看清楚內容

### 試算表選單功能一覽

日常維護都在主試算表上方的 **「志工訪視系統」** 選單完成，不必進 Apps Script。選單在「說明」右邊；若沒看到，重新整理一次試算表即可。

| 選單項目 | 什麼時候用 | 會不會動到資料 |
|---|---|---|
| 🔄 同步題庫欄位 | 在「訪視題庫」新增或停用題目之後 | 只新增欄位 |
| 📋 填入預設連動規則 | 要用「答否自動勾選改善建議」功能時 | 只填題庫的規則欄 |
| 📢 建立系統公告表（跑馬燈） | 第一次要設跑馬燈時 | 已存在則不覆蓋 |
| 🔍 檢查分隊試算表（順便補標題列） | 新增分隊後、或懷疑某分隊沒收到紀錄時 | 只補缺少的工作表與欄位 |
| 🏢 建立分隊專屬試算表（只處理未設定的） | 新增分隊、或要換掉舊格式的分隊試算表時 | 只建新檔，已填 ID 的分隊會跳過 |
| 🗑️ 刪除指定紀錄（依流水號） | 清除測試或錯誤的紀錄 | **會刪資料**，需輸入流水號並確認 |

`initializeSheets` 和 `resetAllSheets` **刻意不放進選單**，因為它們會把人員名冊覆蓋成範例資料、清掉分隊對照表的試算表 ID。真的需要時才到 Apps Script 編輯器執行。

#### 分隊沒收到紀錄時怎麼查

點「🔍 檢查分隊試算表」，它會把分隊對照表上每個分隊跑一遍並逐一回報：

- `✅ 正常（N 筆紀錄）` — 沒問題
- `🔧 已補上 N 個欄位` — 題庫加了題目、分隊表欄位沒跟上，已自動補齊
- `⚠️ 未設定試算表 ID` — 分隊對照表那一列的 ID 欄是空的
- `❌ 打不開試算表` — ID 貼錯（只要網址中間那一串，不是整段網址），或那張表沒分享編輯權給本帳號
- `❌ 第 1 列不是標題列（舊格式）` — 見下一段

**舊格式試算表**指的是從別處沿用、第 1 列直接就是資料的表。同步程式假設第 1 列是標題列，遇到這種表會把整組欄位接到既有資料的**右邊**（例如 BN 欄之後），紀錄確實有寫入、但位置完全不對，而且不會有任何錯誤訊息。程式現在會偵測並**直接跳過不同步**，在執行紀錄寫明原因。要修的話：把「分隊對照表」該列的 ID 清空 → 執行「🏢 建立分隊專屬試算表」產生新表 → 舊表留著當歷史資料。

### 清除測試用的填報紀錄

測試資料會同時存在三個地方，所以**不要只在主試算表刪列**：主試算表「訪視紀錄表」、各分隊專屬試算表的「訪視紀錄」、Drive 資料夾「志工訪視系統_受訪人簽名」裡的簽名圖。

用選單 **「志工訪視系統 → 🗑️ 刪除指定紀錄（依流水號）」** 三個地方會一起處理：

1. **先備份**：主試算表點「檔案 → 建立副本」，各分隊試算表也各做一份。刪除無法復原。
2. 在「訪視紀錄表」看一下要刪哪幾筆，記下**流水號**（第一欄）。
3. 點選單，輸入流水號。可用逗號分隔或連號，例如 `1,2,5`、`1-8`、`1-3,7`。
4. 確認畫面會列出每一筆的日期、案家姓名、分隊，核對沒錯再按「是」。
5. 最後會問要不要一併刪簽名圖。按「是」是移到 Drive 垃圾桶，30 天內還能還原。

幾個要注意的地方：

- **剩下紀錄的流水號不會重新編號**，中間會出現斷號（例如刪掉 3、4 之後是 1、2、5），這是正常的。新紀錄一律接在現有最大號之後，不會撞號。
- 人員帳號管理、分隊對照表、訪視題庫、系統公告**都不會被動到**。
- **不要用 `resetAllSheets`／`initializeSheets` 來清紀錄**。它們會把人員名冊覆蓋成範例資料，並清掉分隊對照表裡的試算表 ID（分隊同步就會斷掉）。
- 志工手機若在離線時填報過測試資料，資料還排在他手機的待送佇列裡，下次連線會自動補送上來。若刪完又冒出測試紀錄，請該名志工在填報頁重新整理並確認已送出，再刪一次即可。

## 🚦 開放各單位測試 → 正式上線

建議的做法是「同一套系統先開放測試，上線前把測試紀錄整批清掉」，不必另外維護一套測試環境。流水號是連號遞增的，測試期的紀錄在主表上必定是連續的一段，用 `1-150` 這種範圍一次就能刪乾淨。

### 開放測試前

- [ ] 跑一次選單的「🔍 檢查分隊試算表」，確認所有分隊都是 `✅ 正常`，不要帶著壞掉的分隊開放
- [ ] **明訂測試期只能填假資料**：案家姓名用假名或統一加「測試」兩字，電話地址隨便填。這是為了避免上線前發現有人拿真案家測過，整批不敢刪
- [ ] 告知各分隊承辦人：**測試期的資料上線前會全部清除**，不要在分隊試算表上做統計或加註記

### 測試期間

- [ ] 收集各單位回報的問題
- [ ] 留意有沒有分隊回報「我這邊都沒收到資料」——這正是驗證同步有沒有通的最好時機，當場用「🔍 檢查分隊試算表」查，不要等上線才發現

### 正式上線前（依序做）

- [ ] **記下分界點**：到主表「訪視紀錄表」看最後一筆的流水號是多少（例如 150）。
      **不要用日期判斷**——「訪視日期」是志工手填的可以隨便改，「填報時間」才是系統蓋的
- [ ] **備份**：主試算表「檔案 → 建立副本」，命名「志工訪視系統_測試期紀錄備份」；分隊試算表若有人做過記錄也一併備份
- [ ] **先試刪 3~5 筆**，看對話框跳出來要多久。清除時除了主表，還要逐一開啟每張分隊試算表各刪一遍，時間主要花在開檔案上，而 Apps Script 單次執行上限是 6 分鐘

- [ ] **確認主表只剩標題列**。全部清光的話，正式第一筆紀錄的流水號會回到 **1**；只要留下任何一筆測試紀錄，新紀錄就會接在最大號之後（留了第 87 筆，正式第一筆就是 88）。要留要清請一次決定，不要留一半
- [ ] 再跑一次「🔍 檢查分隊試算表」，確認每個分隊都是 `✅ 正常（0 筆紀錄）`

## 🔒 分隊資料隔離（進階設定）

若需要各分隊只能看到自己的資料：

1. 用選單的「🏢 建立分隊專屬試算表」產生各分隊的試算表（會自動回填 ID、寫好標題列）
2. 在該試算表的「共用」設定中，僅授予分隊承辦人的 Google 帳號權限
3. 用選單的「🔍 檢查分隊試算表」確認每個分隊都是 `✅ 正常`

志工提交的每筆紀錄，GAS 將自動同步複製至對應分隊的試算表中。

#### 分隊承辦人要給什麼權限？建議「檢視者」

分隊試算表是主試算表的**單向副本**：主表是唯一真相來源，分隊表的任何修改都不會回寫主表。所以給編輯權沒有好處，只有風險：

- 承辦人改了分隊表的數字，主表不會跟著改，兩邊從此對不上，統計以主表為準。
- 刪掉或改動**第 1 列標題列**、把「訪視紀錄」工作表改名，下一次同步就會失敗或把欄位接到資料右邊，而且**不會有錯誤訊息**。
- 刪掉幾列紀錄，主表仍然留著，日後誰也說不清哪邊才對。

承辦人要看、排序、篩選、列印、匯出，用「檢視者」權限全部做得到（排序和篩選請用「建立暫時篩選檢視」，不會影響別人）。要自己加註記，就點「檔案 → 建立副本」在自己的副本上做。

真的需要承辦人在分隊表上標記（例如「已複查」），才給「編輯者」，並約定三件事：**只能在最右邊新增欄位**（欄位是依名稱比對，新增欄位不會被覆蓋）、**不要動第 1 列**、**不要改工作表名稱**。改完請跑一次「🔍 檢查分隊試算表」確認仍是 `✅ 正常`。

#### 要刪除紀錄時，怎麼做才不會弄壞系統

**唯一正確的入口是主試算表的選單「🗑️ 刪除指定紀錄（依流水號）」。** 它會同時處理主表、分隊表與簽名圖，三邊一次清乾淨。

承辦人若發現自己分隊有錯誤的紀錄，請**回報流水號給管理員**，由管理員在主表執行刪除，不要自己在分隊表刪。

| 動作 | 可不可以 | 原因 |
|---|---|---|
| 用選單依流水號刪除 | ✅ | 主表、分隊表、簽名圖一起處理 |
| 只在分隊表刪列 | ❌ | 主表還留著，兩邊對不上 |
| 只在主表手動刪列 | ⚠️ | 分隊表會留下孤兒紀錄，統計會重複 |
| 在最右邊新增欄位 | ✅ | 欄位依名稱比對，不受影響 |
| 刪除或改名既有欄位 | ❌ | 同步會找不到欄位，資料錯位 |
| 刪除第 1 列標題列 | ❌ | 整張表會被當成舊格式，之後不再同步 |
| 改「訪視紀錄」工作表名稱 | ❌ | 同步會另外建一張新的，資料分散兩處 |

刪除前一律先「檔案 → 建立副本」備份，刪除無法復原。

## ❓ 常見問題

**Q：送出表單後沒有資料？**
確認 `frontend/app.js` 的 `GAS_API_URL` 已填入正確網址，且 GAS 部署存取權限設定為「所有人」。

**Q：GAS 修改後前端仍顯示舊資料？**
GAS 有快取機制，每次更新程式碼後需重新部署（部署 → 管理部署作業 → 編輯 → 版本：新版本）。

**Q：手機定位失敗？**
iOS 需使用 Safari 或 Chrome，且網頁必須為 HTTPS（Render 已自動提供）。
